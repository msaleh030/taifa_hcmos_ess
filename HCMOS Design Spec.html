HCMOS™ · Taifa Human Capital Operating System

Visual build specification

The design is a locked decision — it just was never built to. This is the authoritative reference the deployed UI must match, screen by screen. Every screen below embeds its approved prototype render beside token-level redlines, the full state set, and the confidentiality / wording rules. Design-system fidelity is the acceptance bar: if the built screen doesn't match the embed and honour the tokens, it isn't done.

How to read a screen entry. Each carries — a meta row (screen code · source file · role scope · acceptance criteria); the live reference embed (the real approved markup, with the flow's own switcher so you can inspect every state / theme / surface in place); a two-column redline (left: bento layout & the tokens that set it — no raw pixels; right: components used + the rules that gate content); and the full state set that screen must draw.
Tokens over pixels. Per direction, redlines reference the named token (--pad, --r, --gap, grid track counts) rather than measured values, so the build stays parametric. Concrete values live once, in Foundations. styles.css is canonical; where the flow kits diverge it is flagged in F7.
Non-negotiable wording Pay is always Total Pay and Net Pay (Total Pay − Total Deduction) — never “Total Allowance”. Confidential fields are absent, not masked, for roles without entitlement. Generated numbers are TMCL-<LOC>-<SEQ>, non-editable.

Forms

Buttons

One primary per surface (green fill). Secondary is neutral-bordered; ghost is chrome-free; destructive is red text that fills red-soft on hover. Small variant for in-row actions.

Components · K7

Semantic soft-fill pills, no competing borders. Green = healthy/active/on-target, blue = info/assigned/syncing, yellow = watch/pending/offline, red = breach/off-target, grey = neutral/returned. A monospace .flag pill marks [TBC]/[Open] decisions still in review.

  • Wording: Total Pay / Net Pay = Total Pay − Total Deduction.
